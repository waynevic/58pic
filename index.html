开始学习

第 1 章：先认识 Codex（它不是“写代码机器”）

你可以把 Codex 理解成什么？

把它当作“会技术语言的项目助理”：你说业务目标，它把步骤拆解成可执行任务。

  • 你说：做一个活动页面。
  • Codex 会做：生成页面、改文案、优化按钮样式。
  • 你只要看结果、提需求、做决策。
🧠➡️📱

业务想法 → Codex 执行 → 手机上立即预览

业务同学必懂词汇

Prompt（提示词）：你给 Codex 的需求描述。

迭代：不是推翻重来，而是“在上一个版本继续改”。

第 2 章：手机上怎么用（最简单流程）

1

打开移动端 Codex 页面，登录账号。

2

用一句话说明目标：例如“帮我做一个客户活动介绍页”。

3

让它先出“草稿版”，先看结构，再改细节。

4

通过“继续修改”按钮，逐条优化文案、颜色、排版。

手机操作建议：每次只提一个改动点。比如“只改按钮颜色为品牌蓝”，结果更稳定。

第 3 章：Git、分支到底是啥（业务语言解释）

Git = 版本账本

可以理解成“项目修改历史记录本”。每一次保存，都记下是谁改了什么、为什么改。

分支 = 试验副本

主分支是正式版本；你新建分支就像“拿一份副本先试改”，不影响正式线上版本。

主分支（正式版）
↘
活动页优化分支（试改）
↗
合并回主分支（审核通过）

你不用背命令。你只要知道：分支是“安全试错空间”，合并是“审核后上线”。

第 4 章：每个常见功能代表什么（超白话）

功能按钮你可以理解为你该怎么用
New chat新开一个需求会话做新项目时再点，避免把旧需求混在一起。
Edit / Modify继续打磨当前版本一条一条提改动，别一次塞 10 个要求。
Preview手机实时看效果先看是否“能用”，再看是否“好看”。
Commit把改动存档每完成一个小目标就存档，方便回退。
PR (Pull Request)“申请审核后上线”发给技术同学或负责人确认，再合并发布。

第 5 章：你今天就能上手的实战模板

直接复制这段需求给 Codex：

请帮我生成一个手机优先的活动介绍网页：
1）顶部要有活动标题+副标题；
2）中间有 3 个卖点卡片（图标+标题+一句话）；
3）底部有报名按钮；
4）整体配色使用蓝白，风格简洁；
5）所有文字我后续会修改，请先给占位文案。

下一步建议：先让 Codex 生成 v1，再说“只改第2个卡片内容”，循序渐进。

给业务同学的话：你不需要成为程序员，只需要会描述目标、会判断结果。
